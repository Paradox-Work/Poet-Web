# Laravel Telescope Development Tool

## Overview

Poet-Web uses Laravel Telescope as a local development and debugging tool.

Telescope is not part of the application's user-facing functionality. It is used during development to inspect what Laravel is doing internally.

Telescope can show:

- HTTP requests;
- database queries;
- exceptions;
- logs;
- model events;
- cache operations;
- queued jobs;
- commands;
- events.

---

## Installation

Telescope is installed as a development dependency:

```bash
composer require laravel/telescope --dev
```

The Telescope installer generated:

```text
app/Providers/TelescopeServiceProvider.php
config/telescope.php
database/migrations/*_create_telescope_entries_table.php
```

The Telescope database tables are created with:

```bash
php artisan migrate
```

When using Laravel Sail:

```bash
./vendor/bin/sail artisan migrate
```

---

## Local-Only Registration

Telescope is intended only for local development.

Package auto-discovery is disabled in `composer.json`:

```json
"dont-discover": [
    "laravel/telescope"
]
```

`AppServiceProvider` registers Telescope only when:

```text
APP_ENV=local
```

and the Telescope package exists.

This prevents the application from depending on Telescope when production dependencies are installed with:

```bash
composer install --no-dev
```

---

## Opening Telescope

While the application is running locally, Telescope is available at:

```text
/telescope
```

For example:

```text
http://localhost/telescope
```

The exact host depends on the local Laravel/Sail configuration.

## Using Telescope

### Requests

The **Requests** section shows requests received by Laravel.

It can be used to inspect:

- requested URL;
- HTTP method;
- response status;
- request data;
- authenticated user;
- middleware;
- request duration.

This is useful when debugging controllers, validation, Inertia requests, and API endpoints.

### Queries

The **Queries** section shows SQL queries executed by Laravel.

It can help identify:

- unnecessary queries;
- repeated queries;
- N+1 query problems;
- slow database operations.

### Exceptions

The **Exceptions** section records application exceptions and their stack traces.

This is useful when Laravel returns an error and the cause is not immediately obvious.

### Logs

The **Logs** section displays Laravel log entries generated by calls such as:

```php
Log::info(...);
Log::error(...);
```

### Models

The **Models** section shows Eloquent model activity.

This is useful for inspecting database-backed operations involving models such as:

```text
Post
Comment
Group
GroupUser
User
```

## Poet-Web Example

When opening the Poet-Web home page:

```text
GET /
```

Telescope can be opened afterward and the request inspected.

The request entry can show the queries used to load:

```text
posts
comments
reactions
groups
group memberships
```

This makes Telescope useful when checking whether a feature performs unnecessary database queries.

---

## Purpose

Telescope is development tooling only.

It helps inspect and debug Poet-Web during development but does not provide functionality to normal application users.
